1. Motivation Overview

Problem Description
Controlling an object on an underactuated system --- where the top cart has no direct motor or driving belt attached. Its position must be controlled purely through gravity manipulation by dynamically tilting the beam beneath it.
Why It Is Important
Mirrors real-world engineering challenges like anti-sway container crane control, dynamic ship deck stabilization, and self-balancing transport robotics.
Why Selected
Integrates embedded C programming, real-time feedback control theory (PID), microcontroller peripherals (I2C, Timers, PWM), and mechanical linkage synthesis.
Main Objectives
  • Build a physical track rig to dynamically balance the top cart above a target lower cart.
  • Maintain steady-state position accuracy within ±10 mm.
  • Run the control loop deterministically at 100 Hz on ATmega32.

3. System Design Control Fundamentals
5 / 15
Underactuated Gravity Physics
The top cart is passive (no motor or cable attached). Acceleration is generated indirectly by tilting the beam at angle \(\theta\):
\[ F_{\text{net}} = m \cdot g \cdot \sin(\theta) - F_{\text{friction}} \]
Adjusting beam tilt angle \(\theta\) dynamically controls cart acceleration towards target position.
Closed-Loop Error Feedback
Distance sensors continuously measure positions at 100 Hz:
\[ e(t) = X_{\text{lower}}(t) - X_{\text{upper}}(t) \]
The MCU calculates error \(e(t)\) and computes the required beam angle using discrete PID control.
Complete PID Control Equation
\[ u(t) = K_p \, e(t) \;+\; K_i \int_{0}^{t} e(\tau)\, d\tau \;+\; K_d \, \frac{de(t)}{dt} \]
PID Control Term Breakdown
Proportional (P)
\( P_{\text{out}} = K_p \cdot e(t) \)
Provides immediate tilt force proportional to current position error. Drives cart towards target.
Integral (I)
\( I_{\text{out}} = K_i \int e(t) \, dt \)
Accumulates residual error over time to eliminate steady-state offset and overcome track friction.
Derivative (D)
\( D_{\text{out}} = K_d \cdot \frac{de(t)}{dt} \)
Predicts future motion based on error rate of change. Dampens oscillations and prevents overshoot.

4. Role of the ATmega32 Control Steps
8 / 15
Central Embedded Controller
The ATmega32 acts as the single central brain of the system, running bare-metal C at 16 MHz. It executes a continuous 5-step feedback loop every 10 milliseconds (100 Hz) without any operating system overhead.
5-Step On-Chip Execution Loop
Step 1: Distance Data Fetching
Communicates with both VL53L0X laser sensors over I2C at 400 kHz to read current lower cart (\(X_{\text{lower}}\)) and upper cart (\(X_{\text{upper}}\)) millimeter positions.
Step 2: Digital Noise Filtering
Applies a 5-sample software moving-average low-pass filter inside the interrupt routine to remove optical laser reflection spikes.
Step 3: PID Calculation
Calculates error \(e(t) = X_{\text{lower}} - X_{\text{upper}}\), computes P, I, D terms with anti-windup clamping, and maps error to required beam angle.
Step 4: Servo PWM Driving
Converts calculated beam angle into high-resolution 50 Hz PWM electrical pulses (1.0–2.0 ms pulse width) sent directly to the servo motor.
Step 5: Telemetry Streaming
Transmits live position and error numbers over serial interface (115,200 baud) to a PC terminal for real-time graphing and tuning.

The ATmega32 utilizes its built-in hardware peripherals to execute all sensing, timing, motor control, and communications efficiently without needing external helper chips.

OCR0 = 155		 Fires a hardware interrupt (TIMER0_COMPA_vect) every 10 ms (100 Hz). Guarantees deterministic, perfectly timed PID loop execution without timing jitter.
Timer1 (16-bit Counter) Fast PWM Mode 14, /8
ICR1 = 40000, Pin PD5 		Generates a continuous 50 Hz PWM signal with OCR1A pulse width control (1.0–2.0 ms). Provides sub-degree micro-step resolution to tilt the beam smoothly via the servo motor.
Hardware TWI (I2C) Master Mode, 400 kHz
Pins PC0 (SCL) & PC1 (SDA)		 Reads digital distance bytes rapidly from both laser sensors over a shared 2-wire bus. Frees CPU from bit-banging software I2C, allowing high-speed 400 kHz sensor polling.
GPIO Control Pins Digital Output
Pins PB0 & PB1		 Connected to sensor XSHUT reset lines to power up sensors sequentially on boot. Resolves factory default address collision by remapping Sensor 1 to address 0x30.
USART Serial Module TX Mode, 115,200 Baud

6. Microcontroller Selection Design Rationale
12 / 15
No Secondary Microcontroller Required
No additional controller (such as ESP32, Arduino, or Raspberry Pi) is used or required in this project.

Reasoning: The standalone ATmega32 MCU has sufficient built-in hardware peripherals (I2C, 8-bit Timer, 16-bit Fast PWM, USART) to process sensor readings, compute PID math, drive the motor, and stream diagnostic telemetry independently without needing helper boards.

8. Technical Challenges & Future Scope Insights
14 / 15
Challenges & Engineering Solutions
Optical Sensor Noise
Laser distance sensors experienced optical noise spikes.

Solution: Added a 5-sample software moving-average filter inside the 100 Hz interrupt loop.
Linkage Backlash
Mechanical slack in servo gears caused minor jitter near target.

Solution: Applied a ±3 mm software deadband and tuned derivative gain (Kd).
Motor Current Spikes
Rapid motor direction changes caused MCU brownout resets.

Solution: Isolated motor power rail with 5V/3A supply and added 1000 μF capacitor.
Future Enhancements
  • 2D Platform Expansion: Upgrade from 1D beam tilting to a 2D universal ball-joint platform for multi-axis balancing.
  • Advanced Control (LQR): Transition from classical PID to Linear Quadratic Regulator control for improved energy efficiency.
  • Wireless Telemetry: Add Bluetooth module to USART interface for wireless data logging and remote tuning.
